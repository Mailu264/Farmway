# Гайд по Git

Git — это система которая следит за изменениями в коде. Благодаря ней можно вернуться к любой прошлой версии, работать параллельно не мешая друг другу, и отправлять свою работу на проверку.

Мы используем клиент **Fork** — это визуальная программа для работы с Git.

---

## Основные понятия

### Коммит
Коммит — это сохранение твоих изменений с описанием что ты сделала.

**Когда делать коммит:**
- Закончила логически завершённую часть работы (добавила новый сервис, починила баг, добавила анимацию)
- Перед тем как начать что-то рискованное
- В конце рабочего дня

**Когда НЕ надо делать коммит:**
- Код не компилируется
- Ты на полпути и ничего ещё не работает
- Сохранила один файл из пяти нужных

**Хорошее сообщение коммита:**
```
Add player animation service
Fix movement speed bug
Add farm tile interaction
```

**Плохое:**
```
fix
changes
asdfgh
работает!!!
```

### Ветка (Branch)
Ветка — это отдельная копия проекта где ты работаешь не трогая основной код.

`main` — основная ветка, в ней всегда рабочий код.  
Твои фичи — в отдельных ветках.

### Pull Request (PR)
Когда ты закончила фичу и хочешь добавить её в `main` — создаёшь Pull Request. Лид смотрит твой код, оставляет комментарии если нужно, и принимает изменения.

### Stash
Stash — временное хранилище для незакоммиченных изменений. Нужен когда надо срочно переключиться на другую ветку а коммит делать ещё рано.

---

## Как работать с новой фичей — пошагово в Fork

### 1. Убедись что ты на актуальном `main`

В левой панели Fork нажми на `main`.  
Нажми кнопку **Pull** (стрелка вниз) вверху — это подтянет последние изменения от лида.

### 2. Создай новую ветку

`Repository → Branch → New Branch`  
Назови ветку понятно:
```
feature/player-animation
feature/farm-tile
fix/movement-bug
```

Fork переключится на неё автоматически.

### 3. Пиши код и делай коммиты

Когда готова часть работы:
1. В Fork в левой панели нажми **Local Changes**
2. Ты увидишь список изменённых файлов
3. Отметь галочками файлы которые относятся к этому коммиту
4. Внизу напиши сообщение коммита
5. Нажми **Commit**

### 4. Запушь ветку на GitHub

Нажми кнопку **Push** (стрелка вверх) вверху Fork.  
Первый раз Fork спросит — нажми **Push** и подтверди.

### 5. Создай Pull Request

Зайди на GitHub в браузере → в репозитории появится жёлтая плашка с предложением создать PR → нажми **Compare & pull request**.

Напиши что сделала — пару предложений что за фича и как проверить.  
Назначь лида в поле **Reviewers** справа.  
Нажми **Create pull request**.

Всё — лид получит уведомление и посмотрит код.

## Stash — если надо срочно переключиться

Ситуация: ты пишешь фичу, лид просит срочно глянуть баг в другой ветке, а твои изменения ещё не готовы для коммита.

**Спрятать изменения:**  
`Repository → Stash → Stash Changes`  
Напиши название (например `wip animation service`) → **Stash**

Теперь можно переключаться на любую ветку — твои изменения в безопасности.

**Вернуть изменения:**  
В левой панели Fork → **Stash** → правой кнопкой на твой стэш → **Apply Stash**

---

## Если что-то пошло не так

**Сделала коммит с ошибкой в сообщении:**  
В Fork правой кнопкой на последний коммит → **Edit Message** (только если ещё не пушила).

**Случайно изменила файл который не надо:**  
В Local Changes — правой кнопкой на файл → **Discard Changes**. Осторожно — это удалит все изменения в этом файле без возможности восстановления.

**Не знаешь в какой ветке ты находишься:**  
Смотри вверху Fork — там написано текущее название ветки. Или в левой панели — активная ветка выделена жирным.

**Конфликт при Pull:**  
Не паникуй — напиши лиду, разберёмся вместе.

---

## Что НИКОГДА нельзя делать

**Никогда не пушить напрямую в `main`**  
Любые изменения — только через ветку и Pull Request. `main` — это рабочий код который видят все, сломать его значит остановить работу всей команды.

**Никогда не делать Force Push**  
В Fork это кнопка **Push** с галочкой `Force`. Это перезаписывает историю на сервере и уничтожает чужие изменения. Если видишь эту опцию — закрой и напиши лиду.

**Никогда не делать Reset до чужих коммитов**  
`Reset` откатывает твою ветку назад. Если сделать его до коммита который уже запушен и который видят другие — это сломает репозиторий. Если Fork предлагает `Reset` и ты не уверена зачем — не нажимай, спроси лида.

**Никогда не коммитить в чужую ветку**  
Каждый работает в своей ветке. Коммит в ветку другого человека перемешает вашу работу и создаст конфликты.

**Никогда не удалять ветки на GitHub самостоятельно**  
Особенно чужие. Удалить можно только свою ветку и только после того как PR принят.

**Единственное безопасное средство отмены — Revert**  
Если что-то напортачила в своей ветке и хочешь отменить коммит — используй Revert. В Fork правой кнопкой на нужный коммит → **Revert Commit**. Он создаст новый коммит который отменяет изменения — история не ломается, всё безопасно. Можно делать в своей ветке когда угодно.

> Если случайно нажала что-то страшное и не знаешь что произошло — сразу пиши лиду. Чем раньше — тем проще исправить. Git почти всё умеет откатить если действовать быстро.

---

## Коротко — рабочий процесс

```
main (pull) → новая ветка → код → коммиты → push → pull request → лид принимает
```
